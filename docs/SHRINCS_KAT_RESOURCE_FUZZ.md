## Exact portable SHA-256 model

The resource model counts compression blocks in the pinned portable one-shot
SHA-256 implementation. It does not reuse the upstream report's
midstate-cached convention.

For a one-shot input of `n` bytes, the exact block count is:

```text
floor(n / 64) + (1 if n mod 64 < 56 else 2)
```

### Stateful path

For message length `m`, context length `c`, and FXMSS authentication depth `d`,
the exact portable verifier count is:

```text
blocks(75 + c + m) + blocks(73) + 492 + 2d
```

The global admitted-input maximum occurs at `m=4096`, `c=255`, and `d=255`:

```text
1,074 SHA-256 compressions
```

The workflow generates a valid 4,618-byte depth-255 stateful signature and
requires the instrumented verifier to attain that exact count.

### Stateless path

The WOTS-TW verification work depends on a signer-controlled checksum `q` in
`[0,480]`. Its chain-step count is exactly:

```text
45 + q - digit_sum_base16(q)
```

Exhaustive integer evaluation gives a minimum of 45 and a unique maximum of 510
at `q=480=0x1e0`. Combining this with the fixed FORS and five-layer XMSS work
gives a global admitted-input ceiling of:

```text
5,601 SHA-256 compressions
```

This is an analytical ceiling for the current portable verifier, not a selected
consensus cost unit.

## Allocation and parser contract

The current verifier uses one bounded temporary allocation for contextualized
message hashing:

```text
stateful: 75 + context_bytes + message_bytes
stateless: 66 + context_bytes + message_bytes
```

The maximum requests are therefore 4,426 and 4,417 bytes respectively.
Malformed public-key lengths, noncanonical signature lengths, contexts over 255
bytes, and messages over 4,096 bytes must fail before SHA-256 work or allocation.

Static stack usage is collected from GCC `.su` files and must remain below a
4,096-byte per-function research ceiling. That ceiling is a regression guard,
not a final consensus limit.
Dynamic or unknown qualifiers, missing or empty translation units, and missing
emitted helper records fail the evidence check. All nine object/stack-file pairs
are required; GNU `nm` text-function symbols must match the `.su` records for
each unit. Numeric GCC `constprop`, `isra`, and `part` clone IDs are normalized
without merging ordinary functions with clones; ambiguous matches fail closed.
The report retains every parsed record, object function inventory and input
hash, as well as its compact top list. This is not an aggregate call-stack bound.

## Fuzzing

`fuzz_full_verify.c` exposes the combined verifier to libFuzzer using a bounded,
length-delimited input format. The seed corpus contains all eleven regenerated valid
vectors plus key/signature mutations, cross-mode lengths, parser boundaries,
and deterministic noise. `shrincs_fuzz.dict` retains useful comparison
constants discovered by completed campaigns.
The seed CLI independently validates all three frozen corpora, including the
required maximum-envelope corpus, before creating output. It requires an empty,
non-symlink output directory and never deletes existing data. Native statuses other than `0` or `1` fail measurement
and terminate the fuzz driver, rather than counting as ordinary rejection.

Pull requests run a sanitizer-backed smoke campaign. Scheduled runs use a
longer budget after the workflow reaches the protected default branch. Passing
a smoke campaign does not close the sustained-fuzzing gate.

## Hold posture


## First retained run

The first pull-request run on August 16, 2026 passed every resource and fuzz
check. Its machine-readable record is committed as
`contrib/shrincs-ref/evidence-2026-08-16.json`.

The resource job established:

- byte-for-byte regeneration of all nine previously locked KATs;
- a locked maximum-envelope corpus hash of
  `c79cd786bf3cefcce7586cfb018beb3da751ee949b42d3e8afad9e05ea40540a`;
- exact attainment of the 1,074-compression stateful global maximum;
- 11 malformed parser cases rejected with zero SHA-256 work and zero allocation;
- maximum static frame size of 1,024 bytes in
  `pqbtc_shrincs_stateless_verify`;
- bounded temporary allocations of 4,426 bytes statefully and 4,417 bytes
  statelessly.

The sanitizer-backed 121-second fuzz run executed 79,712 units at an average
658 executions per second, reached 129 coverage edges and 244 features, added
76 corpus units, peaked at 387 MiB RSS under ASan/UBSan, and produced no crash,
timeout, out-of-memory condition, or sanitizer finding. The useful comparison
constants discovered during that run are retained in `shrincs_fuzz.dict`.

These are bounded observations from one GitHub-hosted x86-64 runner. They do not
constitute sustained fuzzing, cross-platform resource evidence, or a consensus
performance guarantee.
